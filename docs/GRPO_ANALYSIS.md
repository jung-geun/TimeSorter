# DPO 다음 GRPO — 무엇이 왜 더 좋아지는가

> 작성: 2026-06-11. 파일럿: `configs/grpo_rtx12g_4b_v4.yaml`, 보상 = 골격 규칙(verify_chosen)

## 1. DPO가 구조적으로 못 하는 것

| 한계 | 원인 | 결과 (실측 근거) |
|------|------|------|
| **off-policy negative** | rejected를 프로그램이 chosen 변형으로 생성 — 모델의 실제 오류 분포와 다름 | SFT v3가 보인 "전체 역순 출력"은 v3 negative 5종에 없던 패턴. held-out에서 chain 30%·past_rank 다수가 잔존 |
| **쌍 단위 상대 신호** | "A가 B보다 좋다"만 학습, A 자체가 규칙을 다 지키는지는 모름 | chosen에 없는 조합적 오류(체인은 맞고 날짜는 틀림)는 벌점 불가 |
| **1회성 정적 데이터** | 학습 중 모델이 변해도 쌍은 고정 | 학습 후반 margins 정체 (0.16) — 이미 구분 가능한 쌍에서 추가 신호 없음 |
| **분포 이동 비용** | 새 실패 모드 발견 시 쌍 재생성·재학습 필요 | v2→v3 쌍 전면 재구축에 생성 비용 발생 |

## 2. GRPO가 이를 해결하는 메커니즘

GRPO는 학습 중 **모델이 직접 생성한 k개(=4) 샘플**을 보상 함수로 채점하고, 그룹 내
상대 우위(advantage)를 정책 경사로 쓴다. 이 프로젝트가 GRPO에 특히 적합한 이유:

1. **검증 가능한 보상이 이미 있다 (RLVR)**: verify_chosen()은 결정적이고 비용이 $0이다.
   judge LLM·reward model 없이 지난 일정 순위·동일일 시각 순서·체인 연속성·리스크 importance를
   직접 보상으로 변환한다. 데이터 생성 검증 → held-out 평가 → RL 보상이 **같은 규칙의 단일 출처**.
2. **on-policy**: 모델이 지금 저지르는 실수(예: chain 분산)가 그 스텝에서 바로 음의 advantage를
   받는다. negative를 미리 설계할 필요가 없다.
3. **절대 신호**: 전 규칙 통과(+1.0)와 위반 수 비례 벌점(-0.3/건)으로, "상대적으로 나은" 출력이
   아닌 "규칙을 전부 지키는" 출력을 직접 목표화한다 — eval 지표(전 규칙 통과율)와 최적화 목표가 일치.
4. **ref-free 메모리 이점**: GRPO는 그룹 평균이 baseline이라 DPO처럼 ref logprob 사전계산이
   필요 없다 (KL 페널티용 ref는 어댑터 비활성 트릭 재사용).

## 3. 예상 개선 지점 매핑 (held-out 실측 기준선: dpo_v3 = 56.7% / guard 62.7%)

| 위반 유형 (건수) | DPO가 남긴 이유 | GRPO 기대 효과 |
|------|------|------|
| past_rank 52 | 순서만 틀린 17건 + 점수도 틀린 13건 — negative가 못 가르친 조합 | 생성 샘플 중 past를 위로 둔 것만 즉시 벌점 — 직접 최적화 |
| chain 39 | dependency_scatter negative(346쌍)가 실제 오류 패턴과 다름 | 연속성·순서 위반이 보상에 그대로 반영 |
| intraday_order 12 | granularity_swap이 2-태스크 swap만 커버 | k개 샘플 간 순서 차이가 자연스럽게 대비됨 |

**파일럿 판정 기준**: held-out 150에서 무처리 통과율 56.7% → **+8%p 이상**이면 v5에서
GRPO 본 학습(프롬프트 2K, DGX)으로 확대. KL(beta 0.04)로 JSON 형식·거부 능력 망각을 방지.

## 4. 실행 설계

```
dpo_v3 (시작 정책)
  → GRPO: 프롬프트 384개(취약 시나리오 chain·past 과대표집, build_grpo_prompts.py)
          × 생성 4개/프롬프트, 1 epoch, lr 2e-6, beta 0.04
  → eval_scheduler.py (held-out 150, 학습 미사용 seed 47) 전후 비교
```

주의: GRPO 프롬프트(seed 46/51/53 계열)와 평가셋(seed 47)은 분리되어 있다.
보상 해킹 점검: reason 품질은 규칙에 없으므로, 학습 후 샘플의 reason 길이·다양성을 수동 확인.
