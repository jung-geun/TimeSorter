# Part 3 — 학습 데이터셋 진화 (v1 → v5) & HF 원본 증강

## 3-1. 버전별 입력·출력 변화와 학습 기대효과

전체 흐름: **자유 텍스트(v1) → 4축 JSON(v2) → 날짜 추론(v3) → 이중 생성(v4) → on-policy 보강(v5)**

| 버전 | 출력 형식 | 핵심 추가 | 입력에 추가된 것 |
|------|----------|----------|-----------------|
| v1 | 자유 텍스트 번호 매기기 | 페르소나 기반 우선순위 | 페르소나 + 할 일 |
| v2 | **4축 점수 JSON** | 구조화·앱연동·설명가능성 | (동일) |
| v3 | 4축 JSON | **오늘 날짜 주입·지난 일정 규칙** | `today` 컬럼 |
| v4 | 4축 JSON | **이중 생성 경로·prompt loss 마스킹·신규 시나리오 3종** | (동일, curated) |
| v5 | 4축 JSON | **on-policy DPO·의존성 체인 보강** | (동일) |

---

### v1 — 자유 텍스트 우선순위 (`scheduler_ko_combined`, 5,999행)

**입력:**
```
[주정숙 씨의 오늘의 할 일 목록]
- 작은 언어 모델에 대한 이야기 듣기
- 파이썬 비동기 강연 듣기
- 드론 만들기 해커톤 참여하기
- 디지털 디톡스 명상 세션 참석하기
persona: 주정숙 (건물 경비원, 69세)
```
**출력 (chosen):**
```
1) 작은 언어 모델에 대한 이야기 듣기 - 오늘의 중요한 일이라 꼭 들어야 해.
2) 파이썬 비동기 강연 듣기 - 요즘 젊은 친구들이 많이 하는 거라 한번 들어보면 좋을 것 같아.
3) 드론 만들기 해커톤 참여하기 - 나이 들어도 손재주가 남아 있으니 한 번 해볼 만해.
4) 디지털 디톡스 명상 세션 참석하기 - 늦은 시간이라 너무 피곤할 것 같아.
```
**기대효과**: 페르소나 말투·관점이 반영된 우선순위. **한계**: 자유 텍스트라 앱 파싱 불가, 점수 근거 비구조화.

---

### v2 — 4축 점수 JSON (`scheduler_v2_combined`, 10,958행)

**출력 (chosen)** — v1과 같은 입력이라도 구조화된 JSON으로:
```json
{"tasks":[{"id":1,"text":"웹3 패널 토론 참석하기"}, ...],
 "priority_order":[1,2,3],
 "scores":[{"task_id":1,"urgency":3,"importance":3,"dependency":2,"time_constraint":3,"reason":"..."}]}
```
**기대효과**: 앱 연동 가능, 4축 점수로 정렬 근거를 정량화. **한계**: 날짜 개념이 없어 "어제 마감"과 "오늘 마감"을 구분 못 함 (가장 심각한 실패 모드).

---

### v3 — 오늘 날짜 주입 + 지난 일정 규칙 (`scheduler_v3_combined`, 5,678행)

**입력에 `today` 추가** + 시스템 프롬프트에 "오늘은 2026-08-03 (일요일)" 주입:
```
[김경혜 씨의 오늘의 할 일 목록]   (today: 2026-08-03)
- (2026-08-01 10:00까지) 농협 일자리 상담 신청서 작성   ← 이미 지남
- (2026-08-03 10:00까지) 이력서 정리                    ← 오늘
- (2026-08-08 10:00까지) 고용센터 방문 준비             ← 미래
```
**기대효과**: 절대/상대 날짜를 오늘 기준으로 해석. 이미 지난 일정은 `urgency=1, time_constraint=1`로 강등하고 최하위 배치. → **날짜 혼동 실패 모드 해결** (held-out dated 38%→77%). 골격(`meta`)으로 자동 채점 가능.

---

### v4 — 이중 생성 경로 + 신규 시나리오 (`sft_v4_train`, 6,056행)

**무엇을 바꿨나** (입출력 형식은 v3와 동일, "무엇으로·어떻게 학습하나"를 변경):
1. **데이터 큐레이션**: Opus 4.8 의미 감사로 v2의 결함(persona_fit 3.3, 35% 페르소나-할일 불일치) 정량 확인 → 골격 검증 + persona_fit 4.9–5.0 통과 데이터만 사용.
2. **이중 생성 경로**: OpenAI(gpt-5.4)와 Claude(Sonnet 4.6/Opus 4.8)가 **같은 골격**을 병렬로 채움 (openai 596행 + claude 393행). 둘 다 `verify_chosen()` 통과 필수(97–98%) → 표현 다양성 + 품질 수렴.
3. **prompt loss 마스킹**: ~600토큰 시스템 프롬프트에 걸리던 loss를 제거하고 응답 토큰에만 학습 → **학습 밀도 ~2.5배**.
4. **신규 시나리오 3종**: `past_split`(지난/유효 다수 혼합), `no_today`(날짜 미상 시 '지남' 단정 금지), `am_escalation`(오전 마감+에스컬레이션 urgency=5).

**기대효과**: 전 규칙 통과율 **56.7%→77.3% (+20.6%p)**. past_rank 위반 52→15건.

---

### v5 — on-policy DPO + 의존성 체인 보강 (`dpo_pairs_v5`, 1,368쌍 / `scheduler_v5_claude`, 389행)

1. **on-policy 쌍**: SFT v4 모델이 **실제로 생성한 오답**을 rejected로 사용 (228쌍) → 모델의 진짜 실패 분포를 겨냥.
2. **체인 보강**: Claude가 4–5단계 긴 의존성 체인 시나리오를 추가 생성 (dependency_chain 58행 등).

**기대효과(의도)**: 잔여 약점(체인 43%) 개선. **실측**: 체인은 소량 DPO로 불변 — 체인은 *능력 부재*라 선호 학습보다 **SFT 데이터 증량**이 필요하다는 결론 도출. (DPO의 실제 역할은 성능 보존 + 날짜 추론 미세 개선)

## 3-2. HF 원본 데이터셋 증강 — 왜·어떻게 변형했나

TimeSorter는 두 개의 공개 데이터셋을 **이식(graft)**해서 출발했다.

### 원본 ① [anakin87/events-scheduling](https://huggingface.co/datasets/anakin87/events-scheduling) (영문, 500행)

**원본의 정체**: 시간대가 겹치는 이벤트 목록에서 **충돌 없이 우선순위 점수를 최대화**하도록 고르는 *구간 스케줄링 최적화* 문제.
```
Events:
- Small Language Models talk (01:50 - 03:35)
- Async Python talk (12:40 - 14:10)
- Drone building hackathon (19:36 - 20:51)
Priorities: - Small Language Models talk
→ priority_events: ['Small Language Models talk'], optimal_score: 375
```

**우리 목적에 맞춰 바꾼 점**:
| 원본 | TimeSorter |
|------|-----------|
| 영문 이벤트 | **한국어 할 일**로 번역 (예: "Small Language Models talk" → "작은 언어 모델에 대한 이야기 듣기") |
| 시각 충돌 회피(optimal_score 최대화) | **4축 우선순위 채점**으로 과제 재정의 |
| 시작–종료 시각 구간 | 마감 시각·날짜·의존성·리스크로 확장 |
| 페르소나 없음 | 페르소나 조건부 정렬로 변경 |

> v1의 위 "주정숙" 예시가 정확히 anakin87 0번 행(SLM talk / Async Python / Drone hackathon / Digital detox)에서 왔다 — 직접적 lineage 증거.

**왜 갈아탔나**: anakin87 이벤트는 날짜·마감·선후관계가 없는 추상적 강연 목록이라, 우리 과제(날짜 추론·의존성·리스크)에는 부족했다. → v3부터 **골격(skeleton) 생성기**로 현실적 한국어 일정을 합성하며 원본 이벤트 의존을 점진적으로 제거했다.

### 원본 ② [nvidia/Nemotron-Personas-Korea](https://huggingface.co/datasets/nvidia/Nemotron-Personas-Korea) (한국어, 100만행)

**원본의 정체**: 직업·취미·가족·여행·요리 등 다축으로 묘사된 합성 한국어 페르소나.
```
persona: 전기태 씨는 광주 서구에서 평생 하역 일을 하며 살아온 70대 가장으로,
         투박한 손마디에 삶의 흔적이 배어 있는 성실하고 사교적인 인물입니다.
professional_persona / sports_persona / arts_persona / family_persona ...
```

**우리 목적에 맞춰 쓴 방식**:
- `persona` 요약 + 직업·나이를 추출해 **"이름 (직업, 나이세)"** 형태로 압축 (예: `주정숙 (건물 경비원, 69세)`).
- 이 페르소나를 시스템 프롬프트에 주입 → **같은 할 일 목록도 페르소나마다 다르게 정렬**되도록 학습.
- 100만 페르소나에서 표본을 뽑아 시나리오 골격에 결합 → 다양성 확보.

**왜 필요했나**: TimeSorter는 "범용 정렬기"가 아니라 **"개인 비서"**다. 69세 경비원과 31세 엔지니어의 우선순위는 달라야 한다. Nemotron은 이 페르소나 다양성을 현실적인 한국어로 공급했다.

### 종합 — 이식에서 합성으로

```
[anakin87 영문 이벤트]  ─┐
                          ├→ v1·v2 (이벤트 번역 + 페르소나 주입)
[Nemotron 한국 페르소나]─┘
                                    │
                                    ▼
              v3–v5: 골격 생성기로 현실적 일정 합성
              (날짜·마감·의존성 체인·리스크 — anakin87 원본엔 없던 축)
              + Nemotron 페르소나는 계속 조건부 신호로 유지
```

두 원본을 그대로 쓰지 않고, **이벤트 목록 → 페르소나 조건부 4축 우선순위 채점**이라는 새 과제로 재정의하면서, 부족한 축(날짜·의존성·리스크)은 골격 합성으로 보강한 것이 핵심이다.
