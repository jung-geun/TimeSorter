# 보강 분석 — 포맷(스키마) vs 추론(내용) 분리 채점

> **업데이트 (n=150 전체 평가)**: 이 문서의 수치는 초기 n=30 분석이다. 이후 4B를 전체 held-out n=150으로 재검증한 결과는 — no-adapter 스키마 0%/내용 **34.0%**, base 14.7%/31.3%, SFT·DPO **85.3%**. 패턴(포맷 미준수 vs 추론 능력 분리, SFT=DPO 동일)은 동일하며, 큰 표본에서 수치만 보수적으로 조정됨. 헤드라인 표·차트는 n=150 기준으로 갱신됨([README](../../README.md)).


## 왜 이 분석이 필요한가

no-FT 모델(instruct·base)은 `tasks`를 규격(`[{"id","text"}]`)이 아니라 `["문자열"]`로 출력해
채점기(`verify_chosen`)가 **'JSON 파싱 실패'로 전부 0% 처리**한다. 하지만 이 모델들은
`priority_order`와 `scores`(task_id 포함)는 정상 출력한다.

→ **tasks id를 위치 기반(1..N)으로 재구성**하면, 스키마를 무시하고 **추론 내용(순서·점수)만**
동일한 5종 골격 규칙으로 채점할 수 있다. 이로써 "포맷 미준수"와 "추론 능력"을 분리한다.

> 구현: `scripts/content_eval.py` (재구성 파서) + `scripts/content_benchmark_n30.py` (n=30 재추론)

## 핵심 결과 (held-out n=30)

| 모델 | 스키마 준수 통과 (현행) | 내용만 통과 (신규) | 숨은 추론 능력 |
|------|----------------------|------------------|--------------|
| Qwen3.5-4B (no FT, instruct) | **0.0%** (0/30) | **43.3%** (13/30) | +43.3%p |
| Qwen3.5-4B-Base (no FT) | 16.7% (5/30) | **40.0%** (12/30) | +23.3%p |
| + SFT v4 | 90.0% | 90.0% | 0 (포맷=내용) |
| + DPO v5 | 90.0% | 90.0% | 0 |

**instruct의 "0%"는 거의 전부 포맷 문제였다.** 추론 내용만 보면 43.3%를 맞힌다.
파인튜닝된 모델은 스키마=내용(항상 유효 JSON 출력)이라 갭이 없다.

## 결론 — 파인튜닝이 한 일을 두 종류로 분해

1. **포맷 고정 (가장 큰 즉효)** — 리스크·상대날짜는 instruct가 **내용 100% 이미 정답**.
   SFT는 여기서 추론을 가르친 게 아니라 **출력 규격만 고정**해 0% → 100%로 끌어올렸다.

2. **진짜 추론 보강** — 날짜 혼재(22%→89%), 당일 시각(33%→100%)은 내용 자체가 약했고,
   SFT가 실제 추론을 가르쳤다.

3. **여전히 미해결** — 의존성 체인은 내용 기준으로도 0%(no-FT)→67%(SFT). SFT가 일부 가르쳤지만
   상한이 낮고 DPO로도 안 움직임 → 체인 SFT 데이터 증량 필요 (앞선 결론과 일치).

> **발표 메시지**: "instruct가 0%라 쓸모없다"가 아니라, **"추론 능력의 43%는 이미 있었고,
> 파인튜닝의 1차 기여는 그 능력을 앱이 쓸 수 있는 규격으로 고정한 것"**이다.
> 동시에 날짜·체인 같은 진짜 약점에는 SFT가 실제 추론을 보강했다.

> 내용 실패 시 위반 유형(instruct): 체인 15건 · past_rank 8건 · 당일시각 6건 — 체인이 압도적 약점.
